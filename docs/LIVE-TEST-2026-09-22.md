## Root cause

`captureNative` correctly maps a canonical 1280×720 ROI into the incoming source resolution. Cards, board, pot, stack and fixed-seat presence use this path.

Before commit `be87b71`, `commitmentPixelCanvas` calculated canonical pixel coordinates and passed them directly to `drawImage(video, x, y, w, h, ...)`. At a 1920×1080 source this inspected the wrong location and a crop that was too small.

Example for `right-low`:

- correct 1920×1080 source origin: about `(1133, 488)`;
- old source origin: `(755, 325)`.

The reader therefore returned zero/null values. This caused the cascade:

1. `toCall` could not be derived;
2. preflop zero-commitment reconstruction created false folds;
3. postflop monetary actions became checks at turn transitions;
4. the action history stayed incomplete;
5. the gate blocked all recommendations.

## Implemented corrections

### Resolution-independent commitments

- `commitmentPixelCanvas` now uses `captureNative` just like the already-correct readers.
- The canonical output size remains unchanged, so the frozen numeric template bank remains valid.
- Commitment downscaling disables smoothing. This preserves thin glyphs such as the `4` in `0.04`, which otherwise can resemble `8` after a 1.5× resample.

### False Hero-turn reopen

When physical buttons disappear for more than 280 ms, the runtime stores a fingerprint of the closed epoch. If the buttons return within four seconds, the epoch resumes only if all of these are unchanged:

- hand id;
- street;
- Hero cards;
- board;
- legal action set;
- Hero commitment;
- action count.

Any new action, changed commitment, changed street, changed cards/board or expired window creates a genuine new turn normally.
